# 本机 Pattern 图案库

此包处于独立开发分支，尚未接入 daemon、CLI、HTTP 或 MCP。它保存用户手动导入的定义与固定执行快照，不会播放、恢复旧任务、访问 USB 或写设备 Flash。

## 公共合同

`DefaultDir()` 返回当前普通用户的 `os.UserConfigDir()/nb1/patterns`。`New(dir)` 要求显式绝对路径，只构造对象，不创建目录；`Path()` 显示所选路径。读取不存在的库返回空库，不创建目录。导入才允许创建缺失的管理目录。每次操作重新读取磁盘，并取得同一库的短期跨进程独占锁；竞争返回 `ErrBusy`，没有隐藏重试。

| 方法 | 行为 |
| --- | --- |
| `Import(data)` | 接受严格创作包或冻结快照；先验证全部输入，再合并、检查总量、一次发布 |
| `List()` / `Get(id)` | 返回独立记录；列表按精确 ASCII ID 排序 |
| `Resolve(id, revision)` | 要求完整精确的 `sha256:` 摘要，返回已保存记录及 Program，不创建 Job |
| `Export()` | 返回按 ID 排序的规范冻结包；不写调用者指定的其他文件 |

同 ID、同 revision 且规范内容相同的导入幂等，不重写快照。同 ID 异内容整包拒绝，新记录也不会部分保存。初版没有覆盖、更新或删除。导入结果中的记录、新建 ID 和已有 ID 保留输入次序；库的列表和导出固定排序。上限是整库 128 项、完整冻结包 1MiB，不能通过多次导入绕过。

磁盘上的 `patterns.json` 只接受本包生成的规范、排序后的冻结快照。创作包、非规范 JSON、损坏内容、错误摘要和不支持的编译契约均拒绝；不会静默清空或迁移旧文件。`writer.lock` 是持久协调文件，不在释放锁时删除。未知文件和遗留临时文件保留并报错，供用户检查。

## 发布与失败

写入使用同目录私有临时文件，写全、同步后原子发布。发布前错误保留旧快照；发布已经发生而同步、核验或关闭失败时返回 `ErrCommitUncertain`，不声称未保存、不提供部分成功结果，也不盲目回滚。下一次操作重新核验实际磁盘内容。可见的完整发布与断电耐久是不同的保证，此包的测试不证明突然断电后的恢复。

目录、锁和快照需通过当前用户归属、类型、权限、链接与身份检查；平台实现进一步验证发布前后绑定。它协调本工具的写入者，不是同一账号恶意进程之间的隔离边界。平台安全检查不会通过申请管理员权限或自动修改已有权限来绕过。

## 语义与验证边界

记录复用 `internal/patterns` 的 `nb1-pattern-record/v1` 摘要域及 `nb1-program-effect/v1` 编译合同。旧 `pulse`、颜色 Hex6、Program 默认和结束行为保持原义；本包不添加艺术动作、不做 Gamma 转换，也不将旧 PatternSet 的无限循环解释为新 Program。

验证包括真实临时目录的导入/重开、冲突、总量、深拷贝、严格损坏保留、并发、进程锁、链接与替换，以及可重复注入的发布前后错误。各平台是否已完成原生验收以对应证据为准，交叉编译不能替代原生运行。
