# 最小权限与控制边界

原则是只使用当前功能需要的权限。已有授权不是扩大用途的理由；权限不足时先定位具体进程、设备和调用，不自动提权、重置隐私设置或要求开放全部HID。

| 入口 | 正常功能所需范围 | 不属于该入口的功能 |
| --- | --- | --- |
| HTTP / MCP / daemon模式CLI | 本机HTTP、已配置灯的固定动作和状态 | 打开其他HID、执行命令、管理服务、读取相机 |
| daemon / direct模式CLI | 明确选择的blink(1)、协作锁、必要配置与日志 | 监听键盘、写Flash、访问任意USB设备 |
| 本地服务管理CLI | 当前用户的固定服务配置及启动/停止 | 管理其他用户或任意服务、自动提权 |
| 本地规划站 | 静态规划、证据副本、文件下载 | 控制USB、调用daemon或相机、修改系统权限 |

这是功能边界，不是OS沙箱能力声明。相机观察是开发时显式启用的验证工具，不是灯服务或MCP工具的权限需求。

## 灯控制路径实际能做什么

- daemon只为启动时明确配置的序列号创建worker；设备枚举限定blink(1)的VID/PID，重复序列号/接口不会任选一个打开。真正Open还核对原始path。
- Darwin枚举只读元数据，不调用全量IOHIDManagerOpen/Close。GID仍是通用HID库；显式全量枚举是元数据功能，不表示默认灯服务应打开键盘。
- HTTP/MCP接收固定的灯动作、Program和Effect字段；不提供shell、任意命令、文件路径执行、任意USB报告或Flash写入入口。来自消息或AI的内容也是待校验的数据。
- 任务步数、时间、队列、回执和历史有界；取消与正常退出遵循设备清理约定。同步原生I/O尚无强制取消期限，不能把等待预算说成内核调用已终止。
- CLI的`control run`文件和命令完成通知示例只由本地调用者显式指定。通知包装器执行调用者给出的argv，不解释通知消息为命令，也不属于daemon/MCP的远程执行功能。

## 系统服务和授权

macOS自动管理只操作当前普通用户的固定LaunchAgent。Linux用户服务沿相同方向实现，配置模板使用`UMask=0077`和`NoNewPrivileges=yes`。后者限制服务及其子进程通过execve/setuid等获得新权限，**不是完整沙箱**，也不撤销进程原本拥有的文件访问能力。[systemd说明](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#NoNewPrivileges=)

Windows模板使用当前用户、交互式登录和`RunLevel Limited`，不自动请求管理员权限。它目前是计划任务方案，不是SCM服务，也没有凭模板生成就宣称完成安装验收。

服务管理与硬件控制接口分开：HTTP/MCP没有安装服务、调用launchctl/systemctl或修改系统权限的端点。服务启动、停止和卸载均须由本地CLI明确调用；遇到未知同名配置或归属不明，保留现状并返回可解释的错误。

## 已有保护和仍然存在的边界

HTTP只绑定loopback，并校验Host和浏览器Origin；CLI/MCP客户端禁用代理及重定向。这限制远程访问和跨站请求，但**loopback不是用户认证**：当前API没有令牌或用户身份认证，同机能发出本地HTTP请求的其他进程仍可能控制已配置的灯。它也没有抵御同用户恶意进程的完整隔离保证。

协作式设备锁用于协调本工具，不约束第三方程序或不同账号。文件归属与内容检查可拒绝已经观察到的替换，不承诺对同UID非合作写者提供原子比较删除。

不能将本套件描述为能抵御任意代码注入的完整沙箱。共享主机或接入不可信消息源前，应按实际部署补用户认证、消息来源校验、过期/重放规则和OS隔离，并分别验收；不能用“只监听本地”代替这些能力。云/消息适配器应复用当前灯动作和设备白名单，不扩大为执行命令或操作其他硬件的通道。

## 变更怎样验收

每次新入口都检查：是否仍使用明确设备、是否拒绝未声明动作、是否新增了系统调用/权限需求，以及失败时是否保留未知结果。软件回归、编译符号检查、原生服务生命周期和实际USB验证分别保存；最小权限原则不等于已经完成所有安全验证。
